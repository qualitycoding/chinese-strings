## Decision rules (§3.2) — if → then
| ID | If | Then |
|---|---|---|
| DR-01 | A setup/dependency command fails (apt, pip, FetchContent) | Retry 3× with 30 s, 60 s, 120 s backoff. If a pinned SHA/version is unavailable upstream → halt, BLOCKED.md (never substitute a different version). |
| DR-02 | A frozen test still fails after the step's retry budget, or the implementer believes a frozen test/anchor is invalid | Do not edit tests, fixtures, tolerances or the manifest. Write TEST_CHALLENGE.md (test ID, evidence, proposed fix) and halt; the protocol is re-run from Phase 0 by the planner. |
| DR-03 | T-080 normalised load > 0.45 | In order, re-testing after each: (1) profile and remove per-sample branches/virtual calls in the voice loop; (2) process body/radiation filters once per block-mix rather than per voice where the body is shared; (3) reduce DD body modes of the heaviest instrument to the 8 highest-gain modes (DR-10 log); (4) dispersion sections 4 → 2 only if T-021 still passes. Still failing → BLOCKED.md. |
| DR-04 | tools/osv_check.py reports a vulnerability | Halt, BLOCKED.md with the OSV IDs (security; never suppress). |
| DR-05 | pluginval fails at strictness 10 | Fix the plugin. If the identical failure reproduces with JUCE's own example plugin (AudioPluginDemo) built at the same pin → TEST_CHALLENGE.md (never lower strictness). |
| DR-06 | A JUCE-9-specific defect blocks build or pluginval | D-001 fallback: switch pins to 8.0.15 in CMakeLists.txt and deps.lock.json, log in DEVIATIONS.md, rerun S-001 checks; JUCE 8 API differences are fixed in plugin code only. |
| DR-07 | Windows configure cannot find "Visual Studio 18 2026" | D-012a fallback to "Visual Studio 17 2022"; else BLOCKED.md. |
| DR-08 | auval fails | auval.sh retries once after ad-hoc codesign; still failing → fix AU-specific code; if failure reproduces with JUCE's example plugin → TEST_CHALLENGE.md. |
| DR-09 | A G-003x response is `proceed-with-changes` | Apply exactly the listed DD changes (DR-10), re-render that gate's bundle, rerun the full suite, re-open the same gate once. A second `proceed-with-changes` on the same gate is applied and then treated as `proceed`. |
| DR-10 | Any change to a DD value (DD rows in data/instruments/*.json, or DD constants named in plan/PLAN.md steps) | Allowed only for DD-marked values, only on a gate response or DR-03; append to DEVIATIONS.md: file, field, old, new, reason, gate/DR id. Cited values are never changed (→ DR-02). |
| DR-11 | GitHub-hosted runner label unavailable (image deprecated) | Use the newest label of the same OS family listed in actions/runner-images, log in DEVIATIONS.md. |
| DR-12 | A frozen test passes locally but fails only on one CI OS | Treat as a product defect on that OS (fix code). If caused by a compiler/runtime difference in test support numerics → TEST_CHALLENGE.md. |
| DR-13 | Disk/RAM exhaustion during build (e.g. 1-vCPU/3 GB sandbox) | Build with `-j1`, delete `build*/` and rebuild; if still exhausted, move the step to CI-only execution and record in DEVIATIONS.md. |

**Default rule (verbatim from protocol §3.2):** Choose the most reversible option that does not expand scope, log it in `DEVIATIONS.md` with rationale, and continue — **unless** it touches frozen tests, security, data integrity, a public interface, research integrity, or (upward) a statement's evidence class, in which case halt and write `BLOCKED.md`.
